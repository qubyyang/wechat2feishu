# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

- Added resumable batch export. Every finished article is flushed to disk immediately — rendered output and image bytes alike — so a retry replays those shards from disk instead of re-fetching them. Without this, an export dying on article 150 wastes the quota spent on the first 149, and WeChat's rate-limit penalty can last for hours. Shards go to disk rather than memory because process crashes, container restarts and serverless instance recycling are precisely the failures that kill long jobs, and in-memory state survives none of them. The checkpoint ID is derived by hashing account ID + format + filter, deliberately deterministic instead of a random UUID: on retry the user holds only those parameters and has no ID to pass, so identical parameters must land on the same checkpoint while a different format or filter forks naturally — markdown shards can never be mistaken for pdf output. Restoring is all-or-nothing per article: if the rendered file or any referenced asset is missing, that article falls back to being re-fetched rather than producing a package that looks complete but silently lacks images. Checkpoints are cleared once an export succeeds, stale ones are swept by TTL when listing, and `GET`/`DELETE /api/checkpoint` plus an "unfinished exports" panel expose them. New env vars: `W2F_CHECKPOINT_ENABLED`, `W2F_CHECKPOINT_DIR`, `W2F_CHECKPOINT_TTL_MS`.

- Added full-text search over archived articles. Each body is indexed into `data/search-index.json` during batch export and queried through `GET /api/search` and an "archive search" panel in the console. Indexing happens at export time because the plain text is already in memory — building the index afterwards would mean re-fetching every article from WeChat, and that rate-limited quota is the scarcest resource here. Chinese text is tokenized with bigrams rather than a dictionary-based segmenter: it recalls arbitrary substrings with no dictionary to ship or maintain, and unlike single-character splitting it does not treat 上海 and 海上 as equivalent. Query terms are combined with AND, since archived articles on the same topic are highly similar and OR would drag in weakly related results. The inverted index is rebuilt per query instead of being persisted — the file already stores the full text, so writing postings would double its size while search is a low-frequency operation. Each body is capped at 20,000 characters, and a missing or corrupted index degrades to an empty one so search failures never block export. New env vars: `W2F_SEARCH_INDEX_ENABLED`, `W2F_SEARCH_INDEX_PATH`.

- Added scheduled incremental archiving. Configured accounts are exported on a fixed interval and the resulting ZIPs land in `data/archives/` with timestamped filenames, while per-account run time, result and consecutive failure count are persisted in `data/schedule-state.json`. The service deliberately ships no cron daemon: a Next.js route handler has a completely different lifetime under serverless versus long-running deployments, so an in-process timer would silently vanish on instance recycling and would hit WeChat concurrently across instances. Instead `POST /api/schedule` is an idempotent tick meant to be driven by an external timer — accounts that are not due are skipped, accounts are processed serially so the existing pacing queue is never bypassed, failures still advance the last-run timestamp (rate limiting is the usual cause and tight retries only extend the penalty), and "no new articles" is recorded as skipped rather than failed. The batch export core was extracted from the route handler into `src/lib/account-export.ts` so scheduling calls it directly instead of self-issuing HTTP requests. New env vars: `W2F_SCHEDULE_ENABLED`, `W2F_SCHEDULE_ACCOUNTS`, `W2F_SCHEDULE_INTERVAL_MS`, `W2F_SCHEDULE_FORMAT`, `W2F_SCHEDULE_LIMIT`, `W2F_SCHEDULE_ARCHIVE_DIR`, `W2F_SCHEDULE_STATE_PATH`.

- DOCX and PDF exports now include article images. Both formats previously lost every picture: DOCX dropped them outright, and PDF emitted broken placeholders because `./assets/…` cannot be resolved by `page.setContent()`. Image bytes downloaded during resource localization are now reused directly — DOCX embeds them through `ImageRun`, PDF inlines them as `data:` URIs — so neither path re-fetches from the WeChat CDN, which rejects unauthenticated requests anyway. Dimensions are parsed straight from the file header (PNG/JPEG/GIF/BMP) and scaled to the page width while preserving aspect ratio. Images that failed to download, or use a format DOCX cannot embed such as WebP and SVG, degrade to an inline placeholder so the reading order stays intact.

- Added live progress streaming to account batch export. The console now sends `stream: true`, and the API answers with Server-Sent Events reporting the listing phase, per-article progress (advancing on failures too, so the bar never stalls) and the final packaging step. Because SSE carries text only, the finished ZIP is staged on disk under `data/export-jobs/` and handed over through a second `GET /api/account-export?jobId=…` request that consumes and deletes it. Stale packages are swept on the next export, job IDs are validated as UUIDs to block path traversal, and the non-streaming POST behaviour is unchanged for scripted callers. New env vars: `W2F_EXPORT_JOB_DIR`, `W2F_EXPORT_JOB_TTL_MS`.

- Added PDF, DOCX, MHTML and CSV export formats alongside the existing Markdown and HTML. PDF is rendered through the already-bundled `playwright-core` Chromium (`page.pdf()`), so it needs a local Chrome/Chromium just like the browser fallback does. DOCX is generated with the `docx` library from the converted Markdown (headings, paragraphs, lists and quotes; images are omitted because the WeChat CDN blocks unauthenticated fetches at DOCX build time). MHTML is a hand-written `multipart/related` archive that reuses the assets already downloaded by resource localization, so images travel inside a single file. CSV is a batch-only summary manifest (title / author / published date / url / filename), written with a UTF-8 BOM and a leading-character guard against spreadsheet formula injection. Browser launch code moved into `src/lib/browser.ts` so the verify-page fallback and the PDF renderer share a single entry point.

- Added article filtering to account batch export: title keyword (space-separated tokens must all match, case-insensitive), published-date range (inclusive on both ends), and an original-only switch. Filtering happens while paging the article list, so non-matching articles never reach the expensive body fetch. When a start date is set, paging stops early once a whole page falls before it instead of walking the account's full history. Articles whose original flag is unknown are excluded under original-only.
- Added incremental account export. A dedicated `data/archive-index.json` tracks archived article URLs per account, so repeated exports skip articles that were already downloaded instead of spending WeChat's rate-limited quota on them. The index is deliberately separate from `history.json`, which caps at 100 records and would silently misreport older articles as never archived. A checkbox in the console toggles the behaviour, and the response reports how many articles were skipped. New env var: `W2F_ARCHIVE_INDEX_PATH`.
- Added asset localization for account batch export. Article images (and optionally `mpvoice` audio / `mpvideo` video) are downloaded into an `assets/` folder inside the ZIP, and the exported Markdown/HTML references them via relative `./assets/...` paths. Downloads are serialized through the shared pacing helpers, deduplicated by URL hash across articles, and capped per file; failures degrade to keeping the original remote URL. New env vars: `W2F_ASSET_INTERVAL_MS`, `W2F_ASSET_MAX_BYTES`, `W2F_DOWNLOAD_MEDIA`.
- Added HTML as an export format for both single-article export and account batch export. The HTML output is a standalone, styled document; the format is shared by both export paths and recorded in `manifest.json`.
